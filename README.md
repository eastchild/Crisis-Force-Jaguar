**English** · [Français](#français)

A port of the Famicom/NES vertical shooter **Crisis Force** (Konami, 1991) to the **Atari
Jaguar**, made with **[Claude Code](https://claude.com/claude-code)**, Anthropic's AI coding
assistant. The code in this repository (recompiler, runtime, GPU renderer, DSP sound engine,
test tools) was written by Claude Code, directed and play-tested by a human.

The whole game runs from the original NES ROM.

### How it works

- **Static recompiler** (`tools/recomp6502.py`): translates the game's 6502 code to Motorola
  68000 assembly ahead of time, guided by coverage traces of the original game
  (`assets/trace`: code addresses only, no game data). The 6502 registers live in 68000
  registers, and the 6502 flags are only kept where a later instruction (or the caller of a
  subroutine) actually reads them. Code the traces never reached runs in a 6502 interpreter
  written in 68000 (`source/nes_interp.s`, generated by `tools/gen_interp.py`).
- **Runtime** (`source/nes_runtime.s`, `source/nes_hle.s`): the NES hardware the game relies
  on: memory map, Konami VRC4 mapper (banks, scanline IRQ), PPU and APU registers, joypads.
  Mid-frame raster effects are timed by counting the 6502 cycles of the IRQ handlers and
  scheduling the Jaguar's PIT on the matching line. A few hot routines are rewritten natively
  (sprite builder, joypad reading), and the game's idle loop sleeps (`stop`) until the next
  interrupt instead of polling RAM. Small ROM patches (`tools/rom_patches.py`) add a key
  configuration and the bomb on its own button.
- **GPU renderer** (`source/gpu.s`): at every VBlank the 68000 takes a snapshot of the PPU
  state and of the raster bands of the frame; Tom (the GPU) redraws only what changed: the
  background in 8-bit planes (per-row signatures, tile caches), the sprites in a front and a
  behind layer with the NES priorities. The Object Processor shows the bands and the layers,
  the game's HUD always on top.
- **Sound** (`source/dsp.s`): the NES APU (two pulse channels, triangle, noise, DMC) is
  synthesised on the Jaguar's DSP (Jerry) from the game's own register writes, output in I2S.
- **Hardware rules**: the build checks the 68000 and RISC code against the rules the real
  console enforces but emulators do not (`tools/check_hw_rules.py`).

### Status

The game is playable from the title screen to the stages: options, the seven stages (each one
started and played automatically for 40 seconds in the tests), the first boss played by hand.
The two-player mode has not been tested yet. Automated runs of every stage in MAME show no
error and no dropped frame: 60
frames per second on an NTSC machine, 50 on a PAL machine (like a PAL NES, the game itself
then runs slower). The Jaguar version slows down less often than the original cartridge
(about 1 % of the frames, against 1.5 to 6.5 % for the NES in the same scenes). Testing is
mostly done in MAME (headless, scripted), Virtual Jaguar and BigPEmu; the port has not been
tried on a real console yet.

### Controls

Jaguar **B** = fire, **A** = transform, **C** = bomb, **Pause** = Start (pause). The buttons can
be swapped in the game's **OPTION** menu (**KEY**). The second joypad is read as the NES
second joypad (player 2, not tested yet).

### Building

Requirements:
- Python 3 with `py65` (`pip install py65`), for the recompilation,
- JagStudio, for `rmac`, `rln`, `include/JAGUAR.INC` and `include/Univ.bin`: set `JAGSTUDIO`
  to its `buildfiles` directory (default `D:\source_codes\jagstudio\buildfiles`),
- the original ROM, *Crisis Force (Japan) (En).nes* (SHA-1
  `91030a8ffc22be284eb6f8ebaec4ca9418871d96`), in this directory or its parent (or
  `CRISIS_FORCE_ROM`).

Keep the project in a short path: `rmac` fails with a bare `ERROR!` on very long paths.

```
python build.py              # recompile the game if needed, build output/CrisisForce.j64
python build.py --recomp     # recompile the 6502 code again (tools/recomp6502.py)
python build.py --perfhud    # measurement build: game fps, drawn fps, 68000 idle %, GPU busy %
python build.py --nodraw     # same HUD, nothing drawn: raw 68000 speed
python build.py --autotest --stage N   # test build: automatic play from stage N (1-7)
```

`output/CrisisForce.j64` is a 4 MB cartridge image (BigPEmu, MAME, flash cartridges,
SkunkBoard); `output/CrisisForce.abs` runs in Virtual Jaguar. The test tools in `tools/`
(`recomp_test.py`, `jag_sim.py`, `gpu_regress.py`, `risc_cycles.py`, `dsp_test.py`) also need
`unicorn`, `Pillow` and `capstone`. The development log is in `docs/` (in French).

## Français

**[English](#crisis-force-jaguar)** · Français

Un portage du shoot 'em up vertical Famicom/NES **Crisis Force** (Konami, 1991) sur **Atari
Jaguar**, réalisé avec **[Claude Code](https://claude.com/claude-code)**, l'assistant de
programmation IA d'Anthropic. Le code de ce dépôt (recompilateur, runtime, rendu GPU, moteur
sonore DSP, outils de test) a été écrit par Claude Code, dirigé et testé manette en main par
un humain.

Le jeu complet tourne à partir de la ROM NES d'origine.

### Fonctionnement

- **Recompilateur statique** (`tools/recomp6502.py`) : traduit à l'avance le code 6502 du jeu
  en assembleur Motorola 68000, guidé par des relevés de couverture du jeu d'origine
  (`assets/trace` : uniquement des adresses de code, aucune donnée du jeu). Les registres du
  6502 sont dans des registres du 68000, et les indicateurs (flags) du 6502 ne sont conservés
  que là où une instruction (ou l'appelant d'une sous-routine) les lit vraiment. Le code jamais
  atteint par les relevés passe par un interpréteur 6502 écrit en 68000
  (`source/nes_interp.s`, produit par `tools/gen_interp.py`).
- **Runtime** (`source/nes_runtime.s`, `source/nes_hle.s`) : le matériel NES dont le jeu a
  besoin : carte mémoire, mapper Konami VRC4 (banques, IRQ de ligne), registres du PPU et de
  l'APU, manettes. Les effets de trame en milieu d'image sont chronométrés en comptant les
  cycles 6502 des gestionnaires d'IRQ et en programmant le PIT de la Jaguar sur la ligne
  correspondante. Quelques routines très sollicitées sont réécrites en natif (construction des
  sprites, lecture des manettes), et la boucle d'attente du jeu dort (`stop`) jusqu'à
  l'interruption suivante au lieu de scruter la RAM. De petites modifications de la ROM
  (`tools/rom_patches.py`) ajoutent une configuration des touches et la bombe sur son propre
  bouton.
- **Rendu GPU** (`source/gpu.s`) : à chaque VBlank, le 68000 prend un instantané de l'état du
  PPU et des bandes d'effets de trame de l'image ; Tom (le GPU) ne redessine que ce qui a
  changé : le décor dans des plans 8 bits (signatures de rangées, caches de tuiles), les
  sprites dans un calque devant et un calque derrière, avec les priorités de la NES. L'Object
  Processor affiche les bandes et les calques, le HUD du jeu toujours au-dessus.
- **Son** (`source/dsp.s`) : l'APU de la NES (deux voies carrées, triangle, bruit, DMC) est
  synthétisée sur le DSP de la Jaguar (Jerry) à partir des écritures du jeu dans ses
  registres, en sortie I2S.
- **Règles matérielles** : la compilation vérifie le code 68000 et RISC contre les règles que
  la vraie console impose et que les émulateurs ignorent (`tools/check_hw_rules.py`).

### État

Le jeu est jouable de l'écran titre aux niveaux : options, les sept niveaux (chacun lancé et
joué automatiquement pendant 40 secondes dans les tests), le premier boss joué à la main. Le
mode deux joueurs n'a pas encore été testé. Les parties automatiques de chaque niveau sous
MAME ne montrent ni erreur ni
image sautée : 60 images par seconde sur une machine NTSC, 50 sur une machine PAL (comme sur
une NES PAL, le jeu lui-même va alors moins vite). La version Jaguar ralentit moins souvent
que la cartouche d'origine (environ 1 % des images, contre 1,5 à 6,5 % pour la NES dans les
mêmes scènes). Les tests se font surtout sous MAME (sans affichage, par scripts), Virtual
Jaguar et BigPEmu ; le portage n'a pas encore été essayé sur une vraie console.

### Commandes

Jaguar **B** = tir, **A** = transformation, **C** = bombe, **Pause** = Start (pause). Les
boutons peuvent être échangés dans le menu **OPTION** du jeu (**KEY**). La deuxième manette
est lue comme la deuxième manette NES (joueur 2, pas encore testé).
